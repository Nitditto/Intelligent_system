Deep Learning as Function Composition
Section B — Definitions

Mathematical Definition

A neural network is a parameterized composition of simple differentiable functions:

F(x) = f₃ ∘ f₂ ∘ f₁(x) = f₃(f₂(f₁(x)))

Each layer $f_i$ transforms the feature representation from the previous layer.

Takeaway: Deep learning = composing simple functions into a complex non-linear predictor.

The Building Blocks: Neuron, Activation, Layer
Section B — Definitions

1. Artificial Neuron

z = wᵀx + b

Computes a weighted linear combination of input features plus a scalar bias offset.

2. ReLU Activation

ReLU(z) = max(0, z)

Introduces non-linearity; derivative is 1 for positive inputs and 0 for negative inputs.

3. Dense Layer

f(x) = ReLU(W x + b)

Matrix multiplication mapping vector $\mathbf{x} \in \mathbb{R}^{d_{in}}$ to output vector $\mathbf{y} \in \mathbb{R}^{d_{out}}$.

Takeaway: Linear projections combined with non-linear activation functions form the elementary units of deep learning.

From Vectors to Images: Spatial Topology
Section B — Definitions

Tabular Data ($x \in \mathbb{R}^d$)

Features are unstructured vectors. Order of features is arbitrary; no spatial correlation (e.g. Diabetes dataset).

Image Data ($X \in \mathbb{R}^{C \times H \times W}$)

Features possess 2D spatial grid topology. Nearby pixels are highly correlated; translation invariance is critical.

Takeaway: Image classification requires architectural priors (CNNs) to preserve spatial grid topology.

Convolution, Pooling, and Weight Sharing
Section B — Definitions

2D Spatial Convolution Formula

Y[f,i,j] = ∑ₖ ∑ᵤ ∑ᵥ K[f,k,u,v] · X[k, i+u, j+v] + b[f]
  • Local Connectivity: Kernels operate on small receptive fields ($3 \times 3$).
  • Weight Sharing: The same kernel slides across the entire image.
  • Max Pooling: Reduces spatial dimensions ($2 \times 2$, stride 2).
Takeaway: Weight sharing reduces parameters exponentially compared to dense layers while achieving translation invariance.

Explicit loops over epochs & batches. Manual forward, manual loss, manual backprop, manual parameter update.

Modular API. Explicit epoch/batch loops with automatic gradient tracking (loss.backward()).

Framework Trade-Offs & Encapsulation
Section D — Analysis

Scratch (NumPy)

  • + 100% mathematical visibility
  • + Zero black-box abstraction
  • - Extremely slow training
  • - High development effort

Keras

+ Fastest execution & rapid prototyping
+ Cleanest, minimal code
- Hides low-level mechanics

PyTorch

+ Excellent balance of control & speed
+ Dynamic graph autograd flexibility
- Slight autograd overhead on tiny models

Case Study (Class Weighting): Keras class_weight reweights both classes; PyTorch BCEWithLogitsLoss(pos_weight) reweights positive class only. Same concept, subtle framework differences!
Takeaway: Pick Keras for speed, PyTorch for research flexibility, and Scratch for fundamental learning.

Key Conclusion & Summary
Section D — Conclusion
  • 1. Architectural Equivalence: When datasets, splits, architectures, and hyperparameters are held fixed, all three frameworks achieve near-identical predictive performance (~3% accuracy range).
  • 2. Computational Efficiency: Compiled frameworks (Keras/PyTorch) outperform pure NumPy scratch implementations by up to 20x on 2D convolutional workloads.
  • 3. Abstraction Spectrum: Scratch offers complete mathematical transparency; Keras maximizes developer productivity; PyTorch delivers researchers explicit control with automatic differentiation.
Takeaway: Different names do not imply different machine-learning concepts.

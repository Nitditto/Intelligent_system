\section{Overview}
% =====================================================================

This report studies the recurrent neural network (RNN) on two time-related datasets and implements the same model
three times: \textbf{from scratch} in NumPy (\run{SC}, hand-written forward pass, back-propagation through time and Adam),
in \textbf{Keras} (\run{TF}) and in \textbf{PyTorch} (\run{PT}). The datasets are \textbf{EC}, a service process of an
e-commerce company (Online Retail II: orders and cancellations of 750 products over 604 open days, 432{,}000 windows)
and \textbf{ST}, stock prices (S\&P~500: 350 stocks over 1{,}258 trading days, 429{,}800 windows). Both tasks are
many-to-one regression: a window of past days predicts the next day. All implementations share the data, the split, the
architecture (one vanilla RNN layer with 32 units and a linear head), the starting weights, the optimizer and the
early-stopping rule, so the only thing that changes is the abstraction level. LSTM and GRU are added as extras in Keras
and PyTorch. Run IDs have the form \run{<dataset>-<implementation>-<model>}, for example \run{ST-TF-GRU}.

\textbf{Key takeaways}
\begin{enumerate}
\item \textbf{The three implementations compute the same function.} With identical weights the forward passes differ by
  less than $6\cdot10^{-7}$ and the parameter counts match exactly. After training, the core RNN on EC ends at RMSE
  62.51 / 63.01 / 62.84 (scratch / Keras / PyTorch), a 0.8\,\% spread caused by batch order and the epoch at which early
  stopping fires, not by different mathematics. On ST the three core RNNs are indistinguishable (RMSE 0.0159, 0.0159, 0.0158).
\item \textbf{On EC the RNN learns real structure.} All seven recurrent models reach RMSE 62.0--63.0 against 67.9 for the
  train mean, 81.1 for a seasonal-naive forecast and 82.7 for persistence ($R^2\approx0.44$).
\item \textbf{On ST nothing beats the trivial forecast.} RMSE is 0.0158--0.0159 versus 0.0157 for predicting zero return;
  $R^2$ is slightly negative and directional accuracy (48--51\,\%) is below the 53.1\,\% of always predicting ``up''.
  This is the expected outcome for daily returns, which are close to a random walk.
\item \textbf{Gates help little here and cost a lot.} LSTM/GRU improve EC by 0.5--1.5\,\% and do not help on ST, while
  costing 2--3.5$\times$ the time per epoch and 3--4$\times$ the parameters.
\item \textbf{Cost.} For the vanilla RNN on CPU, the NumPy loop (3.9--4.2 s/epoch) is faster than Keras (6.2--6.5 s) and PyTorch
  (11.2--11.8 s) because the model is tiny; PyTorch is the fastest at inference (about 1.6 ms per 1{,}000 windows).
\end{enumerate}

\section{Theoretical Background of Recurrent Networks}
% =====================================================================

This chapter develops, in the order in which the ideas depend on each other, everything needed to read the rest of the report:
the forecasting task (\ref{sec:task}), the mathematical operators (\ref{sec:ops}), the recurrent cell (\ref{sec:cell}), the loss and the way a network is
trained (\ref{sec:train}), why plain recurrence struggles (\ref{sec:vanish}), the gated cells LSTM and GRU (\ref{sec:gates}), how a forecast is judged
(\ref{sec:eval}) and how the same layer appears in the three implementations (\ref{sec:three}). Every formula was also checked numerically against NumPy,
finite differences, PyTorch autograd and PyTorch's own cells; the numbers quoted are the results of those checks.
Notation: $N$ samples, $T$ window length, $F$ features per step, $H$ hidden size; $x_t\in\mathbb{R}^F$ input at step $t$, $h_t\in\mathbb{R}^H$ hidden state,
$\hat y$ prediction, $y$ target, $L$ loss. Vectors are row vectors, so a layer is written $xW$.

\subsection{Time-Series Data and the Forecasting Problem}
\label{sec:task}

\textbf{Sequences.} In a time series the order carries information: the same value means something different depending on what preceded it. A feed-forward network
receives one fixed-length vector and has no notion of order; a recurrent network reads the observations one step at a time and keeps a memory of what it has read.

\textbf{Windows.} A series of length $L$ with $F$ features is turned into a supervised data set by sliding a window of $T$ steps: each window
$(s_i,\dots,s_{i+T-1})$ is an input and the value that follows, $s_{i+T}$, is its target. This gives $N=L-T$ windows per series and the tensors
\begin{equation}
X\in\mathbb{R}^{N\times T\times F},\qquad y\in\mathbb{R}^{N}.
\end{equation}
For the series $[10,12,11,15,14,18]$ and $T=3$ the windows are $[10,12,11]\!\to\!15$, $[12,11,15]\!\to\!14$ and $[11,15,14]\!\to\!18$ ($N=3$).
When several series share one model (many products, many stocks) their windows are simply stacked along $N$.

\textbf{Many-to-one and many-to-many.} A many-to-one model reads $T$ steps and produces one output from the last state; it is used throughout this report
(next-step regression). A many-to-many model produces an output at every step (for example tagging each word), with the same recurrence and an output layer applied to every
$h_t$ instead of $h_T$ only.

\textbf{Chronological split.} Because the future must not influence the past, the data are divided in time order into train, validation and test periods, never at random.
A window may look back into an earlier period, but its target stays inside its own period. Any scaling statistics are computed on the train period only.

\subsection{Mathematical Operators}
\label{sec:ops}

\begin{itemize}
\item \textbf{Matrix product} $(xW)_j=\sum_i x_iW_{ij}$ mixes the inputs into new values. Example: $(1,2)\begin{pmatrix}1&0&2\\3&1&0\end{pmatrix}=(7,2,2)$.
\item \textbf{Element-wise (Hadamard) product} $(a\odot b)_i=a_ib_i$ implements gates: $(0.9,0.1)\odot(4,4)=(3.6,0.4)$, a gate value of 0.9 keeps 90\,\% of a quantity.
\item \textbf{Hyperbolic tangent} $\tanh(z)=\dfrac{e^z-e^{-z}}{e^z+e^{-z}}\in(-1,1)$, with derivative $\tanh'(z)=1-\tanh^2(z)$. Examples: $\tanh(0)=0$, $\tanh(1)=0.7616$,
  $\tanh(3)=0.9951$ and $\tanh'(3)=0.0099$: a saturated unit passes almost no gradient.
\item \textbf{Sigmoid} $\sigma(z)=\dfrac{1}{1+e^{-z}}\in(0,1)$, with $\sigma'=\sigma(1-\sigma)\le0.25$; its outputs are used as gate values.
\item \textbf{Softmax} $\dfrac{e^{z_k}}{\sum_je^{z_j}}$ turns scores into probabilities ($\mathrm{softmax}(1,2,3)=(0.090,0.245,0.665)$); it is needed for classification and not for the regression heads used here.
\item \textbf{Mean squared error} $L=\frac1N\sum_n(\hat y_n-y_n)^2$ with $\partial L/\partial\hat y_n=\frac{2}{N}(\hat y_n-y_n)$. Example for one sample: $\hat y=0.8$, $y=0.5$ gives $(0.3)^2=0.09$ and gradient $2\cdot0.3=0.6$.
\end{itemize}
The two derivatives above were confirmed against finite differences on a grid of points.

\subsection{The Recurrent Cell}
\label{sec:cell}

The network keeps a state $h_t\in\mathbb{R}^H$ that summarises everything read so far. At every step it combines the new input with the previous state:
\begin{equation}
h_t=\tanh\big(x_tW_{xh}+h_{t-1}W_{hh}+b\big),\qquad h_0=0,\qquad \hat y=h_TW_{hy}+b_y .
\label{eq:rnn}
\end{equation}
The matrices have shapes $W_{xh}\in\mathbb{R}^{F\times H}$, $W_{hh}\in\mathbb{R}^{H\times H}$, $b\in\mathbb{R}^{H}$, $W_{hy}\in\mathbb{R}^{H\times1}$, $b_y\in\mathbb{R}$.
\emph{Unrolling} draws the loop as $T$ copies of the same cell chained through the state (Figure~\ref{fig:unroll}). The copies share their weights, so the number of parameters
\begin{equation}
FH+H^2+H\;(\text{cell})\;+\;H+1\;(\text{head})
\end{equation}
does not depend on $T$: a window of 28 steps and a window of 1000 steps need the same 18 parameters for $F=2$, $H=3$ (cell only), whereas a feed-forward layer on the flattened window
would grow with $T$.

\textbf{Worked step.} Take $F=2$, $H=3$, $h_0=0$, $b=0$, $x_1=(1,-1)$ and $W_{xh}=\begin{pmatrix}0.5&-0.5&0.1\\0.2&0.3&-0.4\end{pmatrix}$. Since $h_0=0$, only the input part contributes:
$z_1=x_1W_{xh}=(0.5-0.2,\,-0.5-0.3,\,0.1+0.4)=(0.3,-0.8,0.5)$ and $h_1=\tanh z_1=(0.2913,-0.6640,0.4621)$.
A hand-written unrolled forward pass reproduces PyTorch's \texttt{nn.RNN} to $3\cdot10^{-8}$.

\subsection{Training a Recurrent Network}
\label{sec:train}

\textbf{Back-propagation through time (BPTT).} Training minimises $L$ by gradient descent. Because $h_t$ depends on $h_{t-1}$, the gradient must travel backwards through every step.
With $z_t=x_tW_{xh}+h_{t-1}W_{hh}+b$:
\begin{equation}
\frac{\partial L}{\partial h_T}=\frac{2}{N}(\hat y-y)\,W_{hy}^\top,\qquad
\frac{\partial L}{\partial z_t}=\frac{\partial L}{\partial h_t}\odot(1-h_t^2),\qquad
\frac{\partial L}{\partial h_{t-1}}=\frac{\partial L}{\partial z_t}\,W_{hh}^\top ,
\label{eq:bptt}
\end{equation}
and because the weights are shared, each of them accumulates a contribution from every step:
\begin{equation}
\frac{\partial L}{\partial W_{xh}}=\sum_{t=1}^{T}x_t^\top\frac{\partial L}{\partial z_t},\qquad
\frac{\partial L}{\partial W_{hh}}=\sum_{t=1}^{T}h_{t-1}^\top\frac{\partial L}{\partial z_t},\qquad
\frac{\partial L}{\partial b}=\sum_{t=1}^{T}\frac{\partial L}{\partial z_t},
\end{equation}
while $\partial L/\partial W_{hy}=h_T^\top\,\frac{2}{N}(\hat y-y)$ and $\partial L/\partial b_y=\frac{2}{N}\sum(\hat y-y)$.
For $T=3$ these formulas agree with central finite differences (maximum absolute error $2.9\cdot10^{-10}$) and with PyTorch autograd (error $\le2\cdot10^{-16}$).

\textbf{Adam.} The gradient $g$ is used by the optimizer Adam with moving averages of the gradient and of its square,
\begin{equation}
m\leftarrow\beta_1m+(1-\beta_1)g,\quad v\leftarrow\beta_2v+(1-\beta_2)g^2,\quad
\theta\leftarrow\theta-\eta\,\frac{m/(1-\beta_1^{k})}{\sqrt{v/(1-\beta_2^{k})}+\epsilon},
\end{equation}
with $\beta_1=0.9$, $\beta_2=0.999$, learning rate $\eta$ and step number $k$. Example: for a first gradient $g=0.5$, $m=0.05$, $v=0.00025$, the bias-corrected values are $0.5$ and $0.25$
and the step is $\eta\cdot0.5/0.5=\eta$: the first step has size about $\eta$ whatever the scale of the gradient.

\textbf{Gradient clipping.} To avoid explosions the gradient is rescaled by its global norm, $g\leftarrow g\cdot\min(1,\tau/\|g\|)$. Example: two gradient blocks with norms 30 and 40 have global norm 50;
with $\tau=1$ the scale is $0.02$, the clipped norm is exactly 1 and the direction is unchanged.

\textbf{Early stopping.} After every epoch the loss on the validation period is evaluated. Training stops when it has not improved for a fixed number of epochs (the patience) and the weights of the best epoch are restored,
which protects against fitting noise.

\subsection{The Vanishing and Exploding Gradient Problem}
\label{sec:vanish}

Repeating the last relation of Eq.~\eqref{eq:bptt} shows that the learning signal reaching step $t$ from the output is a product of $T-t$ factors:
\begin{equation}
\frac{\partial L}{\partial h_t}=\frac{\partial L}{\partial h_T}\prod_{k=t+1}^{T}\operatorname{diag}(1-h_k^2)\,W_{hh}^\top,
\qquad
\Big\|\frac{\partial L}{\partial h_t}\Big\|\lesssim\big(\rho\,c\big)^{T-t}\Big\|\frac{\partial L}{\partial h_T}\Big\|,
\end{equation}
where $\rho$ is the spectral radius of $W_{hh}$ and $c\le1$ is the typical value of $1-h^2$. If $\rho c<1$ the signal \emph{vanishes} exponentially and early inputs cannot influence learning
(a factor 0.5 per step leaves $0.5^{20}\approx10^{-6}$ after 20 steps); if $\rho c>1$ it \emph{explodes} ($1.5^{20}\approx3300$) and the updates become destructive.
A numeric experiment with $T=100$ confirms both regimes: with spectral radius 0.5 the gradient at the first step is below $10^{-10}$ of the last-step gradient, with radius 3 it is above $10^{3}$.
Clipping (Section~\ref{sec:train}) controls explosions; the architecture must be changed to counter vanishing, which is what the gated cells do.

\subsection{Gated Cells: LSTM and GRU}
\label{sec:gates}

A \emph{gate} is a sigmoid output multiplied element-wise onto a quantity, so the network decides how much of it to keep, write or expose.

\textbf{LSTM.} It carries two states, the hidden state $h_t$ and the cell state $c_t$ (the long-term memory):
\begin{align}
i_t&=\sigma(x_tW_i+h_{t-1}U_i+b_i), & f_t&=\sigma(x_tW_f+h_{t-1}U_f+b_f), \nonumber\\
g_t&=\tanh(x_tW_g+h_{t-1}U_g+b_g), & o_t&=\sigma(x_tW_o+h_{t-1}U_o+b_o), \nonumber\\
c_t&=f_t\odot c_{t-1}+i_t\odot g_t, & h_t&=o_t\odot\tanh(c_t),
\end{align}
with input gate $i_t$ (how much new content to write), forget gate $f_t$ (how much memory to keep), candidate $g_t$ and output gate $o_t$.
The update of $c_t$ is \emph{additive}: $\partial c_t/\partial c_{t-1}=f_t$, so with $f_t\approx1$ the gradient passes unchanged through many steps, which counters the vanishing of Section~\ref{sec:vanish}.
Example: $f=0.9$, $c_{t-1}=2$, $i=0.5$, $g=0.4$ gives $c_t=0.9\cdot2+0.5\cdot0.4=2.0$.

\textbf{GRU.} It merges the two states: with reset gate $r_t$, update gate $z_t$ and candidate
$n_t=\tanh\!\big(x_tW_n+b_{in}+r_t\odot(h_{t-1}U_n+b_{hn})\big)$,
\begin{equation}
h_t=(1-z_t)\odot n_t+z_t\odot h_{t-1},
\end{equation}
a convex mixture of the new candidate and the old state, so memory can be preserved when $z_t\approx1$.

\textbf{Cost.} A vanilla cell has $FH+H^2+H$ parameters; a GRU has three such blocks and an LSTM four (one per gate and candidate), so with $F=10$, $H=32$ the recurrent parameters are
1{,}376, 4{,}128 and 5{,}504. Step-by-step hand computations of an LSTM and a GRU step match PyTorch's \texttt{LSTMCell} and \texttt{GRUCell} to within $6\cdot10^{-8}$.

\subsection{Evaluating a Forecast: Baselines and Metrics}
\label{sec:eval}

A recurrent network is only useful if it beats simple forecasts, so every model is compared with baselines:
\emph{persistence} ($\hat y_t=y_{t-1}$), \emph{seasonal naive} ($\hat y_t=y_{t-m}$ for a period $m$), the \emph{train mean} and, for returns, \emph{zero return}.
The metrics, all computed on the test period, are
\begin{align}
\mathrm{RMSE}&=\sqrt{\tfrac1N\textstyle\sum(y-\hat y)^2}, & \mathrm{MAE}&=\tfrac1N\textstyle\sum|y-\hat y|, & R^2_{\text{oos}}&=1-\frac{\sum(y-\hat y)^2}{\sum(y-\bar y_{\text{train}})^2},
\end{align}
where $R^2_{\text{oos}}$ compares the model with the predictor that always outputs the train mean ($R^2_{\text{oos}}<0$ means worse than that predictor). For returns two further scores are used:
the \emph{directional accuracy}, the share of windows where $\operatorname{sign}\hat y=\operatorname{sign}y$ (to be read against the share of the most frequent sign), and the
\emph{information coefficient} (IC), the correlation between $\hat y$ and $y$. RMSE and MAE are reported in the original units (after undoing any scaling or logarithm),
$R^2_{\text{oos}}$ in the scaled space in which the models are trained.

weights and in the number of biases (Table~\ref{tab:mapping}); with the same weights they compute the same function.

Task: the last 30 days $\to$ log return on the next day, one pooled model for all stocks. Baselines: zero return, previous-day
return, always ``up'' and the train mean. The EDA (Figure~\ref{fig:eda-st}) shows why the task is hard: returns have
excess kurtosis 54.2, lag-1 autocorrelation $-0.005$, while \emph{squared} returns have lag-1 autocorrelation $0.094$:
volatility clusters, direction does not.

\subsection{Splitting, Scaling and Evaluation Protocol}

\begin{itemize}
\item \textbf{Chronological split by target day:} first 70\,\% of days train, next 15\,\% validation, last 15\,\% test (EC: train $<$ 2011-05-10 $\le$ validation $<$
  2011-08-25 $\le$ test; ST: train $<$ 2016-08-09 $\le$ validation $<$ 2017-05-10 $\le$ test). Window counts: EC 295{,}500 / 68{,}250 / 68{,}250, ST 297{,}500 / 66{,}150 / 66{,}150.
  A window may look back into an earlier split, but its target never leaves its own split.
\item \textbf{Scaling} (mean and standard deviation) is computed on the train period only.
\item \textbf{Metrics:} as defined in Section~\ref{sec:eval}. EC: RMSE and MAE in units sold (after undoing the transforms), $R^2_{\text{oos}}$ on the log scale. ST: RMSE and MAE in log-return, $R^2_{\text{oos}}$, directional accuracy and information coefficient.
\end{itemize}

\subsection{Architecture}

The core model, identical in all three implementations, is: input $(N,T,F)$ $\to$ one vanilla RNN layer with $H=32$ units and $\tanh$ activation $\to$ last hidden state $h_T$ $\to$ one linear output unit.
It is trained with the mean squared error on the scaled target. LSTM and GRU variants (also $H=32$, one layer) are trained in Keras and PyTorch with the frameworks' default initialisation.

\subsection{Initialisation and Naming}

\textbf{Same weights.} The scratch model draws Glorot-uniform $W_{xh}$, orthogonal $W_{hh}$ and zero biases. The same arrays are copied into
Keras (\texttt{set\_weights}) and PyTorch (transposed). PyTorch has a second bias, which is zeroed and frozen so that the parameter
counts are equal; this is asserted in code. Because the frameworks shuffle with their own generators and Adam's $\epsilon$ is placed slightly
differently in each, training is not bit-identical across implementations; only the starting point is.

\textbf{Naming.} Run ID $=$ \run{<dataset>-<implementation>-<model>} with dataset \run{EC}/\run{ST}, implementation \run{SC} (scratch), \run{TF} (Keras),
\run{PT} (PyTorch) and model \run{RNN}/\run{LSTM}/\run{GRU}. The same ID names the result file, the figures and the table rows.

\section{Implementation Details}
% =====================================================================

\subsection{NumPy Implementation from Scratch}

The class \texttt{ScratchRNN} stores the five arrays $W_{xh},W_{hh},b,W_{hy},b_y$. The forward pass precomputes $X W_{xh}$ for all steps at once and
loops only over time; the backward pass loops from $t=T$ to $1$ applying Eq.~\eqref{eq:bptt}, accumulating the shared-weight gradients,
and also returns $\|\partial L/\partial h_t\|$ for diagnostics. Adam and global-norm clipping are written by hand.

\textbf{Gradient check.} Before training, every parameter of the scratch model is checked against central finite differences
($\epsilon=10^{-6}$, float64, 8 real windows). The error is measured per parameter as $\max|a-n|/\max|a|$:

\subsection{Keras Implementation}

\texttt{Sequential([Input((T,F)), SimpleRNN(32), Dense(1)])}, compiled with Adam (\texttt{global\_clipnorm=1.0}, $\epsilon=10^{-7}$) and MSE;
\texttt{fit} runs shuffled mini-batches with \texttt{EarlyStopping(restore\_best\_weights=True)}. LSTM and GRU replace the first layer.

\subsection{PyTorch Implementation}

A module with \texttt{nn.RNN(F, 32, batch\_first=True)} and \texttt{nn.Linear(32, 1)} applied to \texttt{out[:, -1]}; a hand-written loop does
\texttt{zero\_grad $\to$ forward $\to$ backward $\to$ clip\_grad\_norm\_ $\to$ step} and restores the best state. LSTM and GRU use \texttt{nn.LSTM}/\texttt{nn.GRU}.
These keep two biases, hence their counts differ slightly from Keras's LSTM (by $4H=128$); GRU matches because Keras uses \texttt{reset\_after=True}.

\subsection{Verification That the Three Implementations Agree}

With the same weights, the three forward passes on 64 validation windows differ by at most $4.8\cdot10^{-7}$ (EC: scratch--Keras $4.8\cdot10^{-7}$, scratch--PyTorch $4.8\cdot10^{-7}$,
Keras--PyTorch $6.0\cdot10^{-7}$; ST: $4.8$, $3.6$, $3.3\cdot10^{-7}$), which is float32 round-off, and the parameter counts are identical (1{,}409 and 1{,}217).

\section{Comparison of Implementations and Datasets}
% =====================================================================

\begin{itemize}
\item \textbf{Same code, opposite outcomes.} The architecture, settings and implementations are identical on EC and ST, yet EC is learnable (R$^2\approx0.44$) and ST is not ($R^2<0$).
  The difference lies in the data: weekly and yearly rhythm, order and cancellation counts carry information about next-day demand; daily stock returns carry almost none about the next return.
  The stock result is therefore a negative one, measured against the right baselines.
\item \textbf{Scratch $=$ Keras $=$ PyTorch in function.} On both datasets the three core RNNs start from the same function and end within 0.8\,\% (EC) and 0.03\,\% (ST) of each other; the abstraction level changes the amount of code and the speed, not the learned model.
\item \textbf{Gates} improve a series with long, regular patterns a little (EC) and do nothing for noise (ST).
\item \textbf{Speed.} On CPU with $H=32$ the NumPy loop is the fastest to train; PyTorch pays Python overhead per mini-batch in its hand-written loop (and per-op overhead on tiny tensors), Keras sits in between; PyTorch is the fastest for inference.
\end{itemize}

\section{Conclusions and Limitations}
% =====================================================================

This work covered the concepts of an RNN (sequence tensors, operators, recurrence, BPTT, vanishing gradients and clipping, LSTM/GRU gates), two
time-related datasets of about 430{,}000 windows each, and three implementations of the same RNN (scratch, Keras, PyTorch) that were verified to be the same function
(forward-pass agreement $<10^{-6}$, gradient check $<10^{-9}$, equal parameter counts) and compared fairly. On e-commerce order flow the RNN beats all baselines; on stock returns it
correctly learns that there is nothing to predict.

\textbf{Limitations.} One seed and one chronological split per dataset: differences below about 1\,\% between runs should not be read as a ranking. Hidden size and window length were fixed, not tuned or varied. The ST pool contains survivors of the index (stocks with complete histories), and results describe 2013--2018 only. Timings are CPU-only (TensorFlow has no GPU build on native Windows),
so the speed ranking may change on a GPU. The scratch implementation covers the vanilla RNN only; LSTM and GRU exist in Keras and PyTorch.

\textbf{Code and results.} The three notebooks (\texttt{00\_rnn\_concepts}, \texttt{ec\_retail}, \texttt{st\_sp500}) run top to bottom, each dataset notebook in about 30 minutes on a CPU.
Metrics and training histories of every run are stored as JSON files, and the tables of this report are generated from them. Software: Python 3.13, TensorFlow 2.21 / Keras 3.15, PyTorch 2.14, NumPy 2.5.
